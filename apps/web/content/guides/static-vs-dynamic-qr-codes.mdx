A static QR code stores your content, such as a web address or Wi-Fi details, directly in its pattern, so it can never be changed or tracked, and it works without any service behind it. A dynamic QR code stores a short link that forwards to your destination, so you can change where it goes after printing and count scans. Choose static when the content will never change; choose dynamic when it might, or when you want to know how many people scan.

## What is a static QR code?

A static code is the content itself, written as a pattern of black and white squares. Scan a static web address code and your phone reads the full address straight out of the pattern, then opens it. No server is involved.

That has two consequences. First, a static code can’t expire: there’s nothing to switch off. It will keep working for as long as the print is readable and the destination exists. Second, it can’t be edited. If the address changes, you need a new code.

Static codes are also the only option for some content types. Wi-Fi logins, contact cards (vCards), plain text and calendar events have to be read by the phone directly, so they’re always static.

## What is a dynamic QR code?

A dynamic code stores a short link instead of your destination. On QRfinity it looks like `qrfinity.link/` followed by a few characters. When someone scans it, their phone opens the short link, our redirect service looks up where the code should go, and sends them on.

Because the destination lives in our database rather than in the pattern, you can change it whenever you like from your dashboard. The printed code stays exactly the same. And because every scan passes through the short link, we can count it.

## How do static and dynamic codes compare?

| | Static | Dynamic |

| Change the destination after printing | No, reprint needed | Yes, from your dashboard |
| Scan counts and analytics | No | Yes: total and unique scans, devices, countries |
| Works offline | Yes, for Wi-Fi, vCard, text, events | No, needs a connection |
| Depends on a service | No | Yes, the redirect service must keep running |
| Account needed on QRfinity | No | Yes, a free one |
| Cost on QRfinity | Free, unlimited | Free, unlimited |
| Expires on QRfinity | Never | Never |
| Pattern density | Grows with the length of your content | Stays small, because the link is short |

The last row matters more than it looks. A long web address with tracking parameters makes a static code dense, with many small squares that are harder to scan at small sizes. A dynamic code always holds the same short link, so it stays simple and scans well even on a business card.

## When should you use a static QR code?

Use static when the content is fixed and you don’t need numbers:

- **Wi-Fi and contact cards.** These have to be static anyway.
- **Permanent links.** Your home page, a product’s official manual, a page you control and won’t move.
- **Anything that must work with zero dependencies.** A static code doesn’t rely on us, or on any company, staying in business.
- **Offline places.** Basements, ships, rural venues: Wi-Fi, text and contact codes still work there.

## When should you use a dynamic QR code?

Use dynamic when the destination might move, or when you want to measure results:

- **Printed material that lasts.** Packaging, signage, menus, books and business cards outlive most web addresses.
- **Campaigns.** Posters and flyers where you want to see whether anyone scanned, and from which country.
- **Things you’ll update.** A menu that changes each season, a weekly event page, a PDF that gets a new version.
- **Mistakes.** If the link on a print run turns out to be wrong, you fix it in your dashboard instead of reprinting.

## Why do some dynamic QR codes stop working?

Because the short link belongs to the company that made it. If that company switches the link off, every printed copy stops working at once.
